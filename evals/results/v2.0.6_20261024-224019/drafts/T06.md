# T06: About 2,000-word spec with three questions for applicants

Hello, I can build your lead routing system using n8n and PostgreSQL to automate intake from all four sources, clean and validate leads, and route them correctly. My plan starts with setting up the database schema and tables, followed by building the intake, validation, and storage workflows using n8n and Webhooks. I did nearly this for a B2B SaaS client: Lead entry dropped from about 2 hours a week to under 10 minutes. How would you like to handle the initial database migration on your staging server? Please read the full brief before applying. I am ready to start when you are.

**1. How would you keep the round-robin fair and correct when two leads arrive in the same second?**
I would use a database transaction with a row-level lock in PostgreSQL when reading and updating the round-robin pointer so concurrent executions are serialized safely.

**2. How would you parse partner referral emails that don't follow a fixed format, and what would go to the review queue?**
I would use JavaScript and n8n nodes to extract standard fields where possible, and route any email lacking critical fields or matching no pattern into a dedicated review queue table.

**3. Which part of this project do you see as the biggest risk, and how would you reduce it in the first milestone?**
Parsing unstructured partner referral emails is the biggest risk, which I would reduce in Milestone 1 by implementing robust fallback logging and sending unparsed items straight to the review queue.
