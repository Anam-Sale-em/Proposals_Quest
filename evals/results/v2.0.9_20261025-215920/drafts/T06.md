# T06: About 2,000-word spec with three questions for applicants

Your goal is to build an automated n8n lead routing system that cleans and validates leads, merges duplicates, enriches records, routes them with PostgreSQL rules, notifies reps via Slack, mirrors data to Google Sheets, handles errors, and includes documentation. 1. Design and execute SQL migration files for your PostgreSQL schema including leads, touchpoints, assignments, dead-letter queue, and configuration tables. 2. Build n8n intake workflows for your website demo webhooks, pricing-page chat webhooks, Google Drive webinar CSV polling, and partner referral inbox parsing with a review queue. 3. Implement validation, normalization, duplicate handling, and enrichment logic respecting API rate limits while writing to PostgreSQL and mirroring to Google Sheets. 4. Configure routing rules based on enterprise employee thresholds, country-to-region tables, and PostgreSQL-backed round-robin pointers. 5. Set up Slack notifications, 30-minute claim/reassignment timers, team lead escalations, daily digests, and robust error handling with retries. 6. Deliver Git repository exports, architecture diagram, README documentation, and a recorded 30-minute handover call. I did nearly this: built an n8n workflow with form webhooks, field validation, duplicate checking, Google Sheets rows, and Slack alerts. Lead entry dropped from about 2 hours a week to under 10 minutes. What specific email parsing service or regex libraries do you prefer for extracting unstructured partner referral emails?

**How would you keep the round-robin fair and correct when two leads arrive in the same second?**
I would use PostgreSQL atomic transactions and row-level locking on the round-robin pointer table to prevent race conditions.

**How would you parse partner referral emails that don't follow a fixed format, and what would go to the review queue?**
I would apply flexible JavaScript parsing rules inside n8n to extract core fields, sending any malformed message that misses critical keys directly to the review queue.

**Which part of this project do you see as the biggest risk, and how would you reduce it in the first milestone?**
Variable partner email formats are the biggest risk, and I would reduce it early by building and testing the parsing and review queue logic in Milestone 1.
