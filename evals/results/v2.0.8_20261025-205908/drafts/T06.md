# T06: About 2,000-word spec with three questions for applicants

Your goal is to build an n8n-based lead routing system. I will take in leads from four automatic sources, clean and validate them, merge duplicates, enrich with company size and industry, assign reps using clear rules, send Slack alerts with escalation, store data in PostgreSQL with a Google Sheet mirror, handle errors robustly, and include full documentation for handover. I did nearly this: Built an n8n workflow: form webhooks, field validation, a duplicate check by email, a new Google Sheets row and a Slack alert to the sales channel. Lead entry dropped from about 2 hours a week to under 10 minutes. Please read the full brief before applying.

**1. How would you keep the round-robin fair and correct when two leads arrive in the same second?**
I would use database transactions and row-level locking in PostgreSQL to update the round-robin pointer sequentially.

**2. How would you parse partner referral emails that don't follow a fixed format, and what would go to the review queue?**
I would apply flexible parsing rules with a fallback review queue for any unparseable emails.

**3. Which part of this project do you see as the biggest risk, and how would you reduce it in the first milestone?**
Partner referral email formats varying across companies is the biggest risk, which I would mitigate by implementing robust parsing logic and a review queue early.
